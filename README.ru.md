## Что такое GeDefense TV?

GeDefense TV — приложение безопасности для Android TV OS и Google TV, оптимизированное для
управления с пульта. Оно объединяет локальный слой фильтрации с локальной консолью наблюдения:
показывает, что телевизор делает в сети, что было заблокировано, какие приложения с какими странами
связываются и какие находки действительно проверяемы на устройстве.

Главное правило: **сообщать только то, что наблюдаемо именно на этом устройстве.** Отсутствующие
разрешения, неподдерживаемые API или частичная видимость отображаются как частичная видимость —
никогда как доказательство того, что телевизор «чист». Статус защиты заявляется только тогда, когда
туннель действительно активен.

Приложение — **самостоятельное TV-приложение**. Это не роутер, не межсетевой шлюз и не сетевой
сенсор; оно не интегрируется с прошивкой роутера.

### Почему только локальный loopback-VPN?

GeDefense TV фильтрует трафик прямо на устройстве. Приложение создаёт локальный TUN-интерфейс,
направляет через него собственный трафик и передаёт метаданные DNS и соединений вендорному
проверенному помощнику уровня данных. Отфильтрованный трафик затем уходит с устройства напрямую к
месту назначения.

У такого подхода есть осознанные следствия:

- **Без внешнего сервера, аккаунта и подписки.** Трафик не проходит через сервер VGT или сторонний
  VPN-эндпоинт — нет посредника, которому нужно доверять.
- **Без анализа содержимого.** Оцениваются только метаданные DNS и соединений. Содержимое TLS/QUIC
  остаётся зашифрованным и нетронутым — это не MITM-прокси, и оно не видит внутрь HTTPS.
- **Локальные доказательства.** Находки, счётчики и доказательства остаются на телевизоре. Ничего не
  загружается вовне.
- **Честный отказ.** Если нет согласия, помощник падает или политику нельзя оценить, приложение
  сообщает деградированное/ошибочное состояние вместо тихого пропуска трафика без фильтрации.

## Возможности

### Локальная защита (loopback-VPN)

- TUN-служба на устройстве (`VpnService`, foreground-служба, поддержка Always-On) с вендорным нативным
  помощником для `arm64-v8a` и `x86_64`.
- Запуск/остановка с разовым согласием Android на VPN; необязательный автозапуск после старта приложения.
- Профили фильтрации: **Off**, **Conservative**, **Balanced**, **Strict** — каждый профиль меняет,
  насколько агрессивно обрабатываются известные адреса телеметрии, ACR, рекламы, трекеров и C2.
- Явная модель состояний: Off, Preparing, Active, Limited, Failed, Not supported. «Active»
  показывается только пока локальный туннель действительно работает.
- Живые счётчики: заблокированные потоки, наблюдаемые приложения, активные потоки и объём трафика с
  момента запуска.

### Фильтрация: DNS, трекеры, ACR, реклама и C2

- Локальная оценка DNS-запросов и адресов назначения по вендорному индексу угроз, отобранному каталогу
  трекеров/телеметрии и выбранному профилю конфиденциальности.
- Действия объяснимы: разрешить, аннотировать, коррелировать или блокировать — с причиной из локальной
  политики, а не из удалённого вердикта.
- Ограниченный кэш threat intelligence из публичных списков IOC; устаревшие ленты помечаются, а не
  скрываются.
- Честное ограничение: если приложение использует DNS-over-TLS/HTTPS, его доменные имена не видны;
  приложение говорит об этом вместо догадок.

### Карта трафика с локальной геопривязкой

- Агрегация по приложению, стране и домену для наблюдаемого трафика: байты, активные потоки,
  заблокированные потоки, коррелированные потоки.
- Мировая карта с маркерами стран и маркером происхождения, выведенным из региона/сети телевизора —
  **без GPS и без разрешения на местоположение**.
- Привязка IP→страна использует офлайн-набор данных, загруженный один раз с контрольными суммами
  SHA-256; привязка к стране является оценкой (CDN, anycast и общий хостинг могут определяться неверно).
- Ограниченные и приватные данные: без содержимого, без снимков экрана, без аудио/видео, без
  попакетных журналов.

### XDR-Light

Коррелирует локально наблюдаемое в объяснимые инциденты: повторяющиеся заблокированные потоки по
приложению, заблокированный трафик телеметрии/ACR, впервые замеченный трафик приложения, совпадения с
индикаторами C2 и коридоры в страны высокого риска (только информационно). Каждый инцидент несёт
правило, уверенность, видимость и рекомендацию. Дедуплицировано, ограничено и явно **не** является
привилегированным EDR: без общесистемных потоков, без мониторинга процессов, без заявлений о
целостности прошивки.

### V2.1 Outbound Kinetic-Lite

Детерминированные ограниченные эвристики на скользящих окнах по наблюдаемому исходящему трафику:
всплески DNS, веер адресатов, паттерны beacon, скачки объёма, повторные блокировки, категории
трекеров, совпадения C2 и коридоры высокого риска. Каждая аномалия — это оценка с названными
сигналами, а не вердикт «вредоносная программа».

**По умолчанию только наблюдение.** Временное сдерживание — явный opt-in, доступный только в профиле
«Strict». При включении сдерживаются только префиксы назначения (никогда не приложения), со строгими
ограничениями: не менее двух независимых сигналов, минимальная оценка, известная страна назначения,
короткий TTL (1–30 минут, по умолчанию 10), не более четырёх активных сдерживаний и списки разрешённых
диапазонов платформы, Google и CDN. Любое сдерживание обратимо: появляется TV-попап, пользователь может
нажать **Отменить**, а блокировка снимается автоматически по истечении TTL.

### Первичная настройка с Sir Quacksec

Шестишаговый мастер, управляемый только с пульта: приветствие, принцип локальной защиты, согласие на
VPN, синхронизация threat intelligence (можно пропустить), первая проверка и итог, включающий полную
защиту. Ничего не имитируется: если согласие отклонено или шаг не удался, мастер сообщает об этом.

### Оверлей синхронизации threat intelligence

D-pad-безопасный оверлей показывает прогресс синхронизации публичных лент IOC. Устаревшая или
неудачная синхронизация честно отображается и может быть повторена позже.

### Доказательства, отчёты и экспорт

- Локальный журнал доказательств с HMAC-проверенной цепочкой хэшей и зашифрованными полезными
  нагрузками; fail-closed при потере ключа вместо тихого создания новой цепочки.
- Локальный отчёт безопасности в виде текста и JSON.
- Экспорт через системный файловый диалог (SAF); на TV-образах без диалога документов приложение
  использует резервный путь без разрешений в `Downloads/GeDefenseTV` и сообщает, куда записаны файлы.

### Шесть языков, полная локализация

Английский (по умолчанию), немецкий, французский, русский, упрощённый китайский и японский — полные
наборы ресурсов для каждой строки интерфейса, проверяемые инструментом проверки переводов репозитория.

### Аудит устройства и находки

Помимо фильтрации GeDefense TV сохраняет аудиторскую поверхность только для чтения, с которой
начинался продукт:

- **Состояние устройства:** версия/API Android, отпечаток сборки, ABI и классификация давности
  патча безопасности — это именно метаданные, а не гарантия отсутствия уязвимостей.
- **Видимые приложения:** версия, установщик, дайджесты подписи и статус НОВОЕ/ИЗМЕНЕНО относительно
  базовой линии; ограничения видимости пакетов Android показываются, а не скрываются.
- **Проверки усиления защиты:** ADB/отладка, параметры разработчика, сборки test-keys/userdebug,
  администраторы устройства, службы доступности и установщики вне магазина — трёхзначно, причём
  нечитаемые значения остаются нечитаемыми и никогда не считаются «безопасными».
- **Находки и threat intelligence:** объяснимые находки с серьёзностью, уверенностью и видимостью,
  а также локальная актуальность лент и совпадения индикаторов.

### Честная модель статуса

Модель статуса — это и есть продукт: возможность и видимость являются первичными данными. Вместо
зелёного значка «защищено» вы получаете оценку состояния только при достаточном покрытии, явные метки
частичной видимости и чёткое указание того, что не удалось наблюдать.

## Область применения и ограничения

GeDefense TV намеренно **не является**:

- внешним VPN или сервисом обхода гео-ограничений — сервера нет, и ничего не туннелируется с устройства;
- антивирусом или средством удаления вредоносных программ — он наблюдает сетевое поведение и
  сообщает, но не очищает приложения;
- привилегированным EDR — без доступа к ядру, без root, без общесистемного мониторинга процессов и потоков;
- заменой роутера/шлюза/межсетевого экрана — работает только на телевизоре;
- полным инвентарём приложений — видимость пакетов Android ограничивает то, что приложение может видеть;
- гарантией защиты — фильтрация охватывает только трафик, действительно проходящий через локальный
  путь данных, и только известные ей политики.

Другие известные ограничения:

- **Качество alpha:** реальное TV-железо (устройства OEM) ещё не проверено; текущая база доказательств —
  поведение эмулятора.
- **Видимость DNS:** трафик DoT/DoH скрывает доменные имена от локального наблюдения.
- **Геопривязка приблизительна:** CDN, anycast и общий хостинг могут быть отнесены к неверной стране.
- **Сдерживание временное по замыслу:** короткий TTL, максимум четыре активные блокировки, легко
  отменить — это не постоянное правило межсетевого экрана.
- **Alpha-APK подписан тестовым ключом:** это не production-сборка; для установки нужно разрешить
  неизвестные источники.

## Безопасность и конфиденциальность

- **Без телеметрии, аналитики, рекламы и SDK для сбора сбоев.** В приложении нет сторонних
  runtime-SDK.
- **Без сбора содержимого:** без снимков экрана, аудио, видео или полезной нагрузки; без перехвата TLS.
- **Локальная обработка по умолчанию:** метаданные трафика, находки и доказательства остаются на устройстве.
- **Минимальные разрешения:** `INTERNET`, `ACCESS_NETWORK_STATE`, `FOREGROUND_SERVICE`,
  `FOREGROUND_SERVICE_SPECIAL_USE`, `POST_NOTIFICATIONS` плюс служебное разрешение `BIND_VPN_SERVICE`.
  Без местоположения, доступности, оверлеев, камеры, микрофона и `QUERY_ALL_PACKAGES`.
- **С устройства уходят только публичные данные:** ленты threat intelligence и набор IP→страна
  загружаются по HTTPS; никакие данные устройства не выгружаются.
- **Сообщения об уязвимостях:** см. [SECURITY.md](SECURITY.md). Пожалуйста, не публикуйте
  эксплуатируемые детали в открытых issue.

3. Запустите **GeDefense TV**, пройдите первичную настройку и подтвердите разовый диалог согласия на VPN.
4. Необязательно, через ADB:

```bash
adb connect <tv-ip>:5555
adb install -r VGT_GeDefense_TV_0.2.0-alpha1_VC2_release-debugsigned.apk
adb shell am start -n de.visiongaia.gedefense.tv/.TvMainActivity
```

Alpha-APK **подписан тестовым ключом**. Production-ключ подписи не входит в эту alpha.

## Сборка из исходников

```bash
git clone https://github.com/visiongaiatechnology/gedefense_androidtv.git
cd gedefense_androidtv

export JAVA_HOME=/path/to/jdk-17
export ANDROID_HOME=/path/to/android-sdk

./gradlew :app:assembleDebug           # debug-APK
./gradlew :app:assembleRelease         # release-APK с R8
```

Подпись release читает `GEDEFENSE_RELEASE_STORE_FILE`, `GEDEFENSE_RELEASE_STORE_PASSWORD`,
`GEDEFENSE_RELEASE_KEY_ALIAS` и `GEDEFENSE_RELEASE_KEY_PASSWORD` из окружения. Без них сборка
использует debug-подпись — это нормально для alpha-тестов, но не для распространения. Подробнее:
[BUILD-RUNBOOK.md](BUILD-RUNBOOK.md).

## Тесты

```bash
./gradlew :tv-core:tvCoreCheck     # доменный harness ядра
./gradlew :tv-core:tvV2Check       # harness трафика / приватности / XDR
./gradlew :tv-core:tvKineticCheck  # harness аномалий и сдерживания V2.1
./gradlew :app:lintDebug           # Android lint
```

Harness вендорного ядра (`:core:coreCheck`) требует Linux/macOS JVM: его код долговечных файлов
использует `fsync` каталога, который не поддерживается в Windows. Руководство по эмулятору Android TV,
включая создание AVD и снятие скриншотов, находится в
[docs/TV-EMULATOR-TESTING.md](docs/TV-EMULATOR-TESTING.md). Матрица приёмки — в
[TEST-PLAN.md](TEST-PLAN.md).
